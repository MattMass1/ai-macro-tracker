# Everyday coach candidate contract

Task scoped continuation; not a release authorization.

- `/api/plan` uses only the saved routine and the date-scoped day plan. `has_plan` is true for either; a fresh account returns empty `rotation` and `upcoming`. No fabricated PPL schedule. Today's override changes today's slot only. Assigned exercise/type prefill remains in the existing native logger.
- Today preview confirmation compares routine, session completion, today's stored plan and today's logged exercises under a per-user PostgreSQL advisory transaction lock. All app workout mutation paths take the same lock. Preview is expired after the effective-day boundary, including after lock wait. No schema changes for the lock.
- Voice `log_meal` supports explicitly supplied energy without other nutrients, stored as SQL NULL for protein/carbs/fat/fiber. They never enter the shared food catalog. Exact stated chicken/rice aliases resolve locally with existing sourced serving/estimate labeling. Meal writes still use existing per-user transactional idempotency, duplicate detection and readback; unknown outcomes are not success.
- FoodEntry/Meal nutrient fields are nullable. Calories remain numeric. Day responses expose `macros_complete: false` and `macro_note` for incomplete nutrients. Numeric aggregates (totals, rollups, remaining and averages) are known-only calculations and MUST NOT be presented as complete nutrient totals/remaining values in that case. Both native Today and canvas suppress nutrient progress/remaining; meal subtitles say unknown. Trends add the same flag for daily and weekly windows. Live bootstrap context uses NULL nutrient totals, not zeros. Source fixture `docs/agent-canvas/fixtures/calorie-only-day.json` is generated by Python day_payload and consumed in Swift XCTest.
- Compatibility break for older native builds: nonoptional Double FoodEntry cannot decode NULL. Deploy/migration 003 requires separately approved compatible-client rollout. See `docs/rollback/003_calorie_only_unknown_macros.md`. No schema apply or production enablement implied by these commits.
- Web MealList null presentation updated solely to preserve nullable contract. Web MacroRings has no importing consumer in this tree; no live web dashboard acceptance claimed.

Evidence lives in the private task report directory (not committed into public source): backend RED/GREEN and complete suites, native RED decode and full simulator tests, web tsc/build. Tests with synthetic stores/providers are explicitly not production-provider or PostgreSQL-concurrency evidence.
